## 0. Executive Summary / 执行摘要

**一句话定义：** Luma Admin Console 是 Luma V1 的内部控制台，覆盖角色与人设生产、生成预设、用户管理、商业化配置和数据看板，支撑“官方角色持续供给、对话质量可控、付费链路可监控”的运营目标。

V1 后台服务 5 类角色：

| 角色 | 核心诉求 |
|---|---|
| 运营 | 角色上下架、商业化配置、召回触达、活动节奏 |
| 内容 | 角色人设编辑、示例对话、Gallery/私密资产、生成预设双语维护 |
| 审核 | 用户封禁处置、兜底话术复核 |
| 研发 | 告警与审计、系统设置 |
| 数据 | 四条漏斗看板、Cohort 分层、指标口径管理 |

服务端归属统一对齐 `Luma-PRD-V1.md` 15.1 节：Character / Conversation / AI Orchestration / Media / Wallet / Membership / Moderation / Analytics（另加 Auth/User 支撑用户管理）。

## 1A. 范围分析：后台真正需要 / 不需要 / 操作不了

依据《虚拟人物对话拆解 2》与 C 端 PRD 2.3 Non-Goals，对 V1 后台范围做收敛。以下结论已落实到第 2 章各模块。

### 1A.1 后台真正需要

| 能力 | 说明 |
|---|---|
| 角色内容维护 | Profile、开场白、提示词和视觉资产维护；草稿可直接上架 |
| 生成预设管理 | 照片 15 / 视频 14 标签双语维护与上下架，C 端实时生效 |
| 商业化配置 | 金币包/会员套餐/免费额度直接编辑、保存即时生效 |
| 用户处置 | 重置免费额度、封禁/解封，全部留痕 |
| 数据看板 | 四组埋点看板与分层筛选（只读） |
| 审计日志 | 高危操作留痕（只读） |

### 1A.2 后台不需要（V1 无对应 C 端能力）

| 能力 | 依据 |
|---|---|
| 世界书 / Lorebook | C 端 V1 无设定注入能力，拆解 2 将其列为进阶能力 |
| 主动触达 / 久未上线召回 | C 端 V1 无主动消息功能（拆解 2「主动陪伴」为后续版本） |
| 三层记忆参数配置 | V1 仅短期上下文 + 会话摘要，长期向量记忆为 V1.1+ 路线图 |
| 关系成长 / 好感度 | C 端 Non-Goals 明确排除亲密度体系 |
| 语音 TTS / 通话配置 | C 端 Non-Goals 明确排除语音播放与音视频通话 |
| 对话与模型参数 | 模型路由/Prompt 组装/重锚定/评测等研发侧能力不进入 V1 后台（1.6 移除原只读展示页） |
| 记忆合规 | 记忆策略查看与单会话清除不进入 V1 后台（1.6 移除），隐私清除需求由研发侧工单承接 |
| 审核队列与举报处理 | 不进入 V1 后台（1.7 移除）：安全策略由服务端与审核服务承载，后台仅保留兜底话术维护（并入「生成预设」第四个 Tab） |
| 发布评审流 | 草稿角色直接上架，无需评审环节（1.9 移除） |

### 1A.3 后台操作不了（只读或走流程）

| 项目 | 约束 |
|---|---|
| 已上架角色内容 | 不可直接修改，须点击「修改」生成草稿后编辑再上架 |
| 数据看板与审计日志 | 只读，审计日志只增不改 |

## 2. 模块设计

### 2.1 仪表盘 Dashboard

**用途：** 打开后台即看到全局健康度：核心 KPI、四条漏斗当日概览、需要立即处理的告警。

**页面结构：** 单页两段——KPI 卡区（顶部）、漏斗概览区（四列）。

**KPI 卡：**

| 卡片 | 口径 | 取数来源 |
|---|---|---|
| WAU（每周有效陪伴用户） | 北极星指标，对齐 PRD 11.1 | Analytics |
| 有效对话数 | 用户 ≥3 发且 AI ≥3 回的会话数，日/周 | Analytics |
| 7 日付费转化率 | 新注册用户 7 日内首次付费，目标 ≥3% | Analytics |
| 金币消耗量 | 按解锁私密照片/生成照片/生成视频分层 | Wallet |
| AI 回复成功率 | 目标 ≥98% | AI Orchestration |
| 媒体生成成功率 | 目标 ≥95% | Media |

**漏斗概览：** 展示 `docs/数据埋点.md` 四组（用户、聊天页、金币、会员页转化）的当日各环节量级与转化率，点击跳转第 9 章数据看板对应详情。

**核心操作：** 时间范围切换（今日/7 日/30 日）。

**与 C 端联动：** KPI 与漏斗口径与 C 端埋点事件一一对应，禁止后台另起口径。

**验收要点：**
- KPI 数字与数据看板同口径明细一致。

### 2.2 角色管理

**用途：** 管理官方角色（当前 3 个：露娜 Luna、米拉 Mira、阿梨娅 Aria）的完整生命周期：上架可见、人设编辑、视觉资产、版本发布。

**页面结构：** 角色列表 + 角色编辑器（多 Tab）+ 版本与发布记录。

#### 2.2.1 角色列表

| 列 | 说明 |
|---|---|
| 角色 | 封面缩略图 + 名称（+副标题） |
| 状态 | 「已上架 / 草稿」状态标签；已上架表示 C 端可见，草稿表示改动尚未发布 |
| ID | 角色 ID |
| 标签 | C 端卡片展示标签 |
| 今日聊天用户数 | 与数据看板「聊天页 · 各角色聊天明细」同口径 |
| 消息次数 | 附人均轮次；同口径 |
| 卡曝光 pv/uv | 与数据看板「用户 · 角色卡曝光分布」同口径 |
| 生成提交 → 成功率 | 照片/视频合并的提交数与成功率；同口径 |
| 操作 | 所有状态统一显示「编辑」 |

列表不展示版本号与资产完备度；点击整行或「编辑」均直接进入可编辑表单。状态由「保存草稿 / 上架」操作自动更新，不提供直接切换。

**导入角色：** 列表页右上角仅保留「导入 JSON」，通过 `chara_card_v2` 文件创建草稿并进入编辑器。后台不提供手工新增角色弹窗；创建接口继续保留并由 JSON 导入流程复用。

#### 2.2.2 角色编辑器

角色生产采用 **Profile + Greetings + Character Definition** 三层。Profile 决定用户是否点击，Greeting 锁定第一轮场景和声线，Character Definition 决定跨会话表现。编辑器按实际生产流程收敛为 4 个一级 Tab：角色资料、开场白、角色定义、视觉资产；角色定义不再拆分二级步骤，运营直接维护最终提示词。

**顶部状态与操作：** 已上架与草稿角色进入编辑器后均可立即修改，不再增加二次「修改」步骤。顶部始终显示「保存草稿」和「上架」；保存草稿后列表状态更新为草稿且不影响当前线上版本，上架校验通过后才替换线上版本并更新为已上架。

**左侧角色卡摘要：** 封面大图、名称、副标题，以及该角色的数据指标（今日聊天用户数、消息次数含人均轮次、卡曝光 pv/uv、生成提交→成功率），与角色列表及数据看板同口径；不显示版本号与资产完备度。

**Tab 1 角色资料 / Profile（门面）**

| 字段 | 对应角色卡字段 | 说明 |
|---|---|---|
| Name / 角色名 | name | C 端卡片与聊天标题 |
| Tagline / 一句话定位 | tagline | ≤50 字符，角色卡辅助定位 |
| AI 标识 | AI badge | 常量展示，不可关闭（不伪装真人原则） |
| 标签（双语） | tags | 黑色圆角文字标签，建议 ≤4 个 |
| Description / 角色简介 | description | 以角色自己的声音写，用于资料页与发现卡；前端显示实时字符数，不限制历史内容编辑 |
| Avatar notes | avatar_notes | 内部视觉生产备注（风格、情绪、表情、颜色），不进入模型上下文 |

**Tab 2 开场白 / Greetings（运行时第一条消息）**

| 字段 | 说明 |
|---|---|
| Primary Greeting | 主开场；新会话默认使用，重置对话恢复此条；≤4,096 字符 |
| Alternate Greetings | 主开场之外最多 5 条；每条 ≤4,096 字符，可启停；每条必须提供不同的场景或对话起点 |

开场白必须直接进入场景，使用角色自己的声音，并给用户一个容易回应的动作、问题或选择；禁止使用“你好，我能帮你什么”式通用开场。

**Tab 3 角色定义 / Character Definition（提示词）**

运营直接维护最终交给模型的角色提示词，不再拆分创作规划、定义结构、对话示例、行为规则或最终预览。原有结构可以作为提示词写作参考，但不在后台形成重复字段。

| 字段 | 类型 | 说明 |
|---|---|---|
| 中文提示词 | 多行文本 | 必填；最大 32,000 字符；支持 `{{char}}` 和 `{{user}}` |
| English Prompt | 多行文本 | 必填；最大 32,000 字符；支持 `{{char}}` 和 `{{user}}` |
| 字符统计 | 只读 | 按当前语言实时显示 `n / 32,000` |

**发布检查：** 中英文提示词均非空且未超过 32,000 字符；主开场中英文均非空且未超过 4,096 字符。检查不通过时点击「上架」停留在角色定义 Tab 并提示补充，不改变版本状态。

> 运行时记忆、安全兜底、金币、亲密度和其他系统规则仍不属于角色提示词后台配置。

**Tab 4 视觉资产**
- 封面支持本地上传（角色资料 Tab 同步可更换）。资产分两个子 Tab 管理：**公开资产**（封面 + Gallery 图片）与**私密资产**（私密照片 + 视频封面）；两个子 Tab 均支持多选上传（即时预览）、逐张删除（hover × + 确认）、上下架切换。私密照片维持独立模糊预览与 40 金币定价；私密素材不得被生成器或其他未解锁页面引用。

#### 2.2.3 版本流转

| 规则 | 说明 |
|---|---|
| 版本状态机 | 草稿 → 已上架 → 编辑并保存为新草稿 → 再次上架；仅草稿、已上架两种列表状态，无评审环节 |
| 已上架可编辑 | 点击列表「编辑」后可立即修改；未保存内容不更新状态，保存草稿后状态变为草稿，原线上版本持续生效 |
| 保存草稿 | 仅保存当前后台改动，不影响 C 端；保存后仍保持草稿状态 |
| 上架 | 执行发布校验，通过后创建版本快照、替换线上版本，并将状态更新为「已上架」 |
| 版本快照 | 每次发布保存完整快照，支持一键回滚与版本间 diff |
| 生效范围 | 上架后新会话立即生效；进行中的会话沿用启动时版本直至会话重置 |

**核心操作：** 创建草稿、上架、回滚、下架（下架后 C 端首页与搜索不可见，已有会话保留只读）。

**与 C 端联动：** 角色上架 → 首页 For you 卡片流与角色搜索可见；问候语 → 新会话初始消息与重置对话恢复内容；标签/简介 → 首页卡片与资料页；OOC 话术 → 对话运行时的出戏兜底。

**验收要点：**
- 未发布草稿的任何改动不影响 C 端。
- 草稿可直接上架，无评审中间态；已上架角色也可以进入编辑器立即开始修改。

### 2.3 生成预设

**用途：** 管理 C 端聊天内照片/视频生成能力的标签预设与生成成本。视觉资产（封面 / Gallery / 私密照片）并入角色管理，在角色编辑器「视觉资产」Tab 中维护（见 2.2.2 Tab 4）。

**页面结构：** 四个 Tab——预设管理、生成价格、免费额度、兜底话术。

#### 2.3.1 预设管理

照片（15 标签）与视频（14 标签）两个区块，每行：标签名、预设提示语（中英可编辑）、上下架开关、删除（需确认）；每个区块顶部「+ 新增预设」（标签名 + 提示语，确认后插入并默认上架）。

| 字段 | 说明 |
|---|---|
| 模式 | 照片 / 视频 |
| 标签文案 | 双语（zh/en）展示文案 |
| 预设提示语 | 双语，点击标签时填入 C 端生成卡片输入框 |
| 排序 | 标签在 C 端横向滑动行中的顺序 |
| 状态 | 上架/下架；下架后 C 端不再展示，改动实时生效 |

当前预设清单以 C 端 PRD 为准：照片——随机/自拍/摆姿势/坐姿/近景/微笑/侧脸/回眸/街头/咖啡馆/居家/窗边/夜景/运动/旅行；视频——随机/对镜/眨眼/转身/微笑/挥手/散步/跳舞/喝咖啡/唱歌/伸懒腰/比心/日常/害羞。

#### 2.3.2 生成价格

| 配置 | 默认值 | 说明 |
|---|---|---|
| 图片生成价格 | 20 金币 | 展示在 C 端生成卡片成本位，可直接编辑保存 |
| 视频生成价格 | 40 金币 | 同上 |
| 私密照片解锁 | 40 金币 | 逐张解锁，展示在锁定卡成本位；私密素材不得被生成器或其他未解锁页面引用 |

#### 2.3.3 免费额度

| 配置 | 默认值 | 说明 |
|---|---|---|
| 非会员每日免费消息数 | 10 | `FREE_MESSAGE_LIMIT` 服务端对应值；会员不限对话；全局生效，V1 不支持按用户分组差异化 |

#### 2.3.4 兜底话术

自 1.7 起并入本模块（原「安全与审核」模块仅保留此能力）：未成年人 / 自伤与危机 / OOC 出戏三张话术卡，文案可编辑（双语维护），保存后立即对新会话生效。

**核心操作：** 预设双语编辑与排序、上下架（C 端实时生效）。

**与 C 端联动：** 预设改动 C 端实时生效；成本展示与扣费同源，价格改动与 C 端展示同步生效（避免展示价与扣费不一致）。

**验收要点：**
- 下架标签后 C 端生成卡片标签行即时移除。
- 私密照片原图不出现在任何未解锁链路返回体中（含缩略图与预览 URL）。

### 2.4 用户管理

**用途：** 查询用户、排查问题（支付/会话/会员）、执行处置。

**页面结构：** 用户列表 + 用户详情（多 Tab）。

#### 2.4.1 用户列表

| 列 | 说明 |
|---|---|
| 用户 ID | 静态 ID，精确/模糊搜索 |
| 昵称 | — |
| 注册时间 | — |
| 会员状态 | 非会员 / 有效会员（含到期日） |
| 金币余额 | 当前余额 |
| 会话数 | 累计会话数 |
| 状态 | 正常 / 已封禁 |
| 操作 | 「详情」打开用户详情；「流水」直接进入该用户金币流水页 |

#### 2.4.2 用户详情

| Tab | 内容 |
|---|---|
| 资料 | 头像、昵称、性别、简介、语言、注册渠道 |
| 会员 | 当前套餐、有效期、开通/续费记录；支持会员状态开关（开通可选 1 / 3 / 12 个月时长），修改即时同步 C 端 |
| 金币流水 | 抽屉内展示最近 3 条摘要；「查看全部流水」进入独立流水页（时间/类型/变动/变动后余额/备注，类型含购买/解锁/生成/退款/后台补币，支持按类型筛选），与金币记录页同口径 |
| 会话 | 会话列表与最近消息检查（查看会话需高危权限并留痕） |
| 各角色人设 | 该用户各会话的 Chat Persona |

#### 2.4.3 处置操作

| 操作 | 说明 |
|---|---|
| 重置免费额度 | 将该用户当日免费消息计数（默认 10 条）清零，用于客服补偿 |

### 2.6 数据看板

**用途：** 按简化埋点 `docs/数据埋点.md` 的四组（用户 / 聊天页 / 金币 / 会员页转化）配置的长期看板，供数据与业务团队分层分析。

**页面结构：** 顶部为日期范围选择（开始日期 / 结束日期两个原生日期控件，默认当天，不可选未来日期，起止倒置时自动对调）+ 用户类型筛选（全部 / 游客 / 非会员 / 会员），下方按四组 Tab 组织（用户 / 聊天页 / 金币 / 会员页转化，默认「用户」Tab）；每个 Tab 含 KPI 行 + 主题明细表 + 近 7 日趋势表，明细口径与 `docs/数据埋点.md` 逐行一致。

| 分组 | 环节（与埋点事件对应） |
|---|---|
| 用户 | `app_open`（DAU，区分游客/非会员/会员）→ `home_character_impression`（角色卡曝光 pv/uv） |
| 聊天页 | `chat_view`（每日聊天用户数）→ 预设选择（`media_generation_submit`，preset=custom 单独统计）→ 生成提交→成功（`media_generation_result`）→ 私密照片点击→解锁（`private_photo_unlock_click/result`） |
| 金币 | `coin_store_view`（钱包曝光，区分来源）→ `coin_pack_purchase`（档位偏好）→ `coin_purchase_result`（付费转化）→ `coin_transaction`（消耗分布）；含金币不足拦截弹窗曝光（source=insufficient_dialog） |
| 会员页转化 | `membership_view`（会员中心曝光，区分来源）→ `membership_plan_select`（套餐偏好）→ `membership_purchase_result`（开通/续费）→ `membership_expire`（会员留存）；含免费额度弹窗曝光（source=quota_dialog） |

**筛选规则：** 以单日基准数据为底，缩放系数 = 范围天数 N（含起止）× 日波动系数（由开始日期 hash 确定性映射到 0.90–1.10）× 用户类型系数（游客 ×0.32、非会员 ×0.56、会员 ×0.13）；百分比与人均值不缩放；顶部显示当前范围可读文案（如「2026-07-18 ~ 2026-07-24 · 共 7 天」）；近 7 日趋势表固定显示、不随筛选变化。选择「游客」时，金币与会员页转化 Tab 标注「游客不产生付费数据」，仅保留趋势表。

**分层维度：** 仅保留用户类型（guest / free / member）一个维度；角色、语言、渠道、客户端版本维度 V1 不提供。

**推荐看板（对齐 C 端 PRD 12.6）：** DAU 分层（游客/非会员/会员）、聊天与生成转化（预设偏好、生成成功率、私密解锁率）、金币漏斗（曝光→档位支付→支付成功→消耗分布）、会员漏斗（曝光→套餐选择→开通/续费→到期留存）。

**核心操作：** 看板查询保存与分享、指标口径说明悬浮卡（与 `docs/数据埋点.md` 对齐）、明细导出（数据角色）。

**与 C 端联动：** 全部口径以 C 端埋点与服务端事实表为准，前端/后端差异在看板上标注取数来源。

**验收要点：**
- 任一环节的指标定义可在页面内查看且与 `docs/数据埋点.md` 文字一致。
- 同口径下看板数字与仪表盘 KPI 卡一致。

## 3. 后台与 C 端的数据流

以下链路描述后台动作如何传导到 C 端，作为研发联调与 QA 验收的对照表。

### 3.1 角色上架 → C 端首页可见

1. 内容同学在角色编辑器完成 4 个一级 Tab，并通过 Definition 发布前检查后保存草稿。
2. 草稿编辑完成后直接上架，状态更新为「已上架」。
3. Character Service 更新角色 `status=online`，C 端 `GET /characters` 返回该角色。
4. C 端首页 For you 卡片流、角色搜索、资料页立即可见；新会话以该版本的 `first_mes` 问候开场。
5. 下架反向执行：首页与搜索不可见；已有会话保留，不删除历史与解锁状态。

### 3.2 生成预设改动 → C 端实时生效

1. 内容同学在媒体资产 → 生成预设中编辑双语提示语或上下架标签。
2. 保存生效后 Media Service 下发最新预设清单（C 端打开生成卡片时拉取，或短缓存失效）。
3. C 端生成卡片上方的标签行即时更新；用户点击标签填入的是新提示语。

### 3.3 审核命中 → 私密照片下架

1. 输出审核或举报命中某私密照片 → 进入审核队列。
2. 审核同学处置“下架” → Media Service 将该资产置为不可见并吊销签名 URL。
3. C 端即时生效：角色 Gallery 移除该图（含已解锁用户）、聊天内该消息展示为不可用占位、会话 Gallery 同步移除。
4. Wallet 侧不做自动退款（下架属内容安全处置）；如需补偿走用户管理人工加币并留痕。

### 3.4 商业化配置 → C 端展示与扣费同源

1. 运营修改金币包/会员套餐/免费额度并保存生效。
2. Wallet/Membership Service 更新配置并失效 C 端缓存。
3. C 端钱包页、会员中心、配额弹窗与扣费逻辑读取同一份配置，保证展示价 = 成交价、额度提示 = 实际限制。

### 3.5 告警 → 处置 → 闭环

1. Analytics/服务端事实表触发告警（回复失败率、生成失败未补偿、账实差异）。
2. 仪表盘告警区出现条目 → 值班同学认领 → 跳转对应模块处置（降级模型/处理补偿队列/对账）。
3. 处置完成标记已处理，告警与处置结果进入审计与稳定性看板。

## 4. 非目标（V1 后台不做什么）

与 C 端 PRD 2.3/5.2 的 Non-Goals 对齐，V1 后台明确不做：

- 不做用户创角审核流：C 端无用户创建角色，后台不提供创角提交、素材生成审核、发布分成等任何创作者链路。
- 不做礼物配置：无礼物商城、礼物资产库、礼物定价与动效管理。
- 不做亲密度规则配置：无经验来源、等级权益、防刷策略的配置页面。
- 不做 TTS/音色管理与通话配置：无语音播放、语音/视频通话对应的音色、计费、中断策略配置。
- 不做社区与社交关系管理：无关注/粉丝/Moment/动态审核。
- 不做世界书：C 端 V1 无 Lorebook 设定注入能力，后台不提供任何世界书管理（原 V1 简化版关键词触发方案随 1.2 范围收敛移除）。
- 不做多地区定价与商店对账后台：地区化定价、恢复购买、商店侧报表依赖渠道后台，不在 V1 自建。
- 不做 A/B 实验平台与灰度发布：角色列表仅草稿/已上架两种状态，不提供按比例灰度、通用实验分流与显著性分析。
- 不做客服工单系统：帮助与反馈仅做状态流转与回复模板，完整工单/IM 客服后续接入第三方。
